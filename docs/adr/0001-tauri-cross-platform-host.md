# ADR-0001：采用 Tauri 2 作为三端独立宿主

- 状态：已确认
- 日期：2026-07-24
- 决策来源：用户确认

## 背景

DEM Studio 当前作为 Lens 内嵌 Web 插件运行，但已经拥有独立的输入、计算、渲染、设置和导出闭环。WebGL、大栅格和导出负载与 Lens 共用宿主会扩大故障和资源影响范围，也阻碍独立发布。

## 决定

DEM Studio 迁移为位于 `H:\DEM Studio` 的独立 Tauri 2 产品，使用同一套前端代码支持 Windows、macOS 和 Linux。

第一阶段保留现有 Web 业务实现，仅替换宿主接口与构建方式。Rust 负责桌面能力边界；DEM 算法不会仅因迁移而重写为 Rust。

## 直接影响

- Lens 生命周期与快照消息不再是产品运行前提。
- 设置、预设和最近文件迁入应用数据目录。
- 文件对话框与二进制写入由 Tauri 提供。
- 外部 CDN 依赖进入本地构建产物。
- 三个平台分别构建、签名和发布，不能在 Windows 上生成可信的 macOS 成品。

## 放弃的替代方案

### 继续作为 Lens 插件

无法建立进程隔离，也无法形成独立三端发布链。

### 单独使用 pywebview

迁移成本更低，但会继续携带 Python 运行时，不利于长期独立产品的发布体积、权限边界和原生扩展。

### 全量 Rust 重写

当前没有证据表明 Three.js 渲染和现有解析逻辑必须重写。全量重写会同时改变宿主与业务语义，缺少可控回归边界。

## 可推翻条件

- Tauri 在目标平台无法满足必要的 WebGL/文件能力；
- 实测发布与维护成本显著高于替代方案；
- 产品方向不再要求三端独立发布。
