# BUG-2026-07-31：Babylon 材质语义与画面亮度漂移

## 症状

- 白模按钮已选中，但地形仍呈中灰，明暗层次被压扁。
- 自然材质切换成功后画面接近黑褐色，原有暖色调难以辨认。
- 修改任意地形参数后，快捷样式按钮取消高亮，而材质实际仍保持白模。
- 旧 Harness 只验证设置值和网格存在，因此画面明显错误时仍可通过。

## 根因

迁移层保留了 Three.js 的颜色与灯光参数，却没有保留其渲染语义：

1. CSS/十六进制颜色未经 sRGB 到线性空间转换便进入 Babylon PBR。
2. `toneMapping` 兼容属性没有真正修改 Babylon 图像处理配置。
3. 旧 `RectAreaLight` 被点光源模拟，距离衰减使地形尺度变化时照度崩塌。
4. Three 的灯光强度直接沿用到 Babylon PBR，白模和自然材质均欠曝。
5. 快捷样式高亮依赖 `renderPreset`，而任意设置变化都会清空该字段，造成
   “显示状态”和“真实材质状态”分离。

原设计允许该问题发生，是因为验收 Oracle 只覆盖状态和调用链，没有覆盖最终
画布的亮度、层次、色彩度以及 UI 语义一致性。

## 根因级修复

- 所有作者输入的 CSS/hex 颜色在进入 Babylon PBR 前转换到线性工作空间。
- 白模使用 Babylon KHR PBR Neutral，其他材质使用 ACES。
- 离线软主光改为无距离衰减的方向补光，不再用点光源冒充区域光。
- 分别标定白模与自然材质的主光、天光、补光和曝光；白模增加小幅中性自发光
  下限，避免阴影面退化为脏灰，同时保留可测的亮度跨度。
- 快捷样式状态由真实 `materialMode` 推导，HUD 同时显示材质与地形形态。

## 永久回归 Oracle

Release Harness 必须在 WebGPU 和 WebGL2 上读取真实画布像素：

- 地形前景覆盖率不低于 5%，且至少包含 1000 个采样像素。
- 白模：中位亮度不低于 0.55、亮部低于 0.985、亮度跨度不低于 0.08，
  Neutral 色调映射和白模 UI 状态一致。
- 自然材质：中位亮度不低于 0.22、亮部低于 0.985、亮度跨度不低于 0.06、
  平均色彩度不低于 0.025，ACES 和自然材质 UI 状态一致。
- 两种后端均不得出现 shader/effect 错误或 context loss。

## 禁止的修复

- 不得仅修改背景色或 UI 高亮掩盖材质错误。
- 不得只抬全局曝光直至高光截断。
- 不得把像素闸门替换为设置值、截图非空或人工口头确认。
- 不得恢复 CDN 灯光资源或 Three.js 兼容后端。
