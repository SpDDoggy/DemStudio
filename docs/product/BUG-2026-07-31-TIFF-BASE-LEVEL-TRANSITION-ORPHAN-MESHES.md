# BUG-2026-07-31：TIFF 基座层级切换遗留孤儿网格

## 症状

从 512 档 L2 切到 1024 档 L3 后，新基座可以完成，但旧 L2 Babylon 网格仍可能
留在场景和 GPU 中。它们已不属于新 residency，因而不会再被正常生命周期
统计或释放。

## 根因

质量变化会创建新的 `TerrainResidency`，但旧实现只替换状态对象，没有先判断
新旧基座的几何身份是否兼容，也没有在 L2→L3 这类基座层级变化时统一取消
请求、清空上传队列并销毁旧网格。

现有设计允许问题的原因是“状态重建”和“GPU 资源所有权转移”是两条独立
路径，没有一个包含数据集、构建代次、基座层级及几何设置的生命周期签名。

## 根因级修复

- 用 `baseSignature` 绑定数据集修订、地形构建代次、基座层级、NoData 填充
  与平滑设置。
- 只有签名和基座层级均相同，才可原样收养 ready base、resident refinement、
  在途集合、对象身份和计数。
- 基座层级或几何签名变化时，先提升选择代次、取消宿主请求、清空请求/上传
  队列，再逐个释放旧瓦片网格和 GPU 字节，最后建立新基座。
- L3 上的 1024↔2048↔4096 切换可保留同一基座及兼容精化；降档只释放超过
  新目标层级的精化。

## 永久回归 Oracle

1. 同签名 L3 质量切换必须保留基座和精化网格对象身份及 GPU 字节。
2. L2→L3 不得收养旧基座，新的 `readyBaseTiles` 初始为空。
3. 层级变化后的旧 tile key 不得继续出现在 Babylon 场景、GPU 统计或阴影
   caster 列表。
4. 真实 1024 金样最终只拥有 64 个 L3 完成记录；42 个有效网格和 22 个
   NoData empty 合计必须等于 required，旧层级计数为 0。

## 禁止的修复

- 不得只把旧网格设为不可见而继续占用无所有者的 GPU 内存。
- 不得清空整个场景或重开数据集来掩盖质量切换泄漏。
- 不得破坏 2048/4096 共用完整 L3 基座的对象连续性。
